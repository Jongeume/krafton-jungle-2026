# 9.6.3 다중 레벨 페이지 테이블

> 진척도 이슈 : [#204](https://github.com/Jongeume/krafton-jungle-2026/issues/204)

> [!NOTE]
> **요약**  
> 페이지 테이블을 **여러 단계로 쪼갠다.**  
> 안 쓰는 구간의 표는 아예 만들지 않는다.  
> 대신 번역할 때 PTE 를 단계 수만큼 읽는다 → TLB 가 메운다.

> [!TIP]
> **비유**  
> 전화번호부를 "지역 → 동" 두 단계 색인으로 나눈다.  
> 사람이 안 사는 지역은 동 색인 책자를 아예 만들지 않는다.  
> 대신 번호 하나를 찾을 때 색인을 두 번 펼친다.

## 그림 9.17 — 두 단계 페이지 테이블 계층

![study-09-fig-9-17-two-level](assets/study-09-fig-9-17-two-level.svg)

### 왜 필요한가

- 페이지 테이블을 한 덩어리로 두면 너무 크다  
    - 32비트 · 4KB · PTE 4B → 프로세스마다 4MB  
    - 48비트 · PTE 8B → 512GB  
- 그런데 프로그램은 주소공간의 극히 일부만 쓴다

### 아이디어

- 표를 **여러 단계로 쪼개서**, 안 쓰는 구간의 표는 만들지 않는다

### 구조 (32비트 · 4KB 페이지 · PTE 4B)

- 레벨 1 : PTE 1024 개  
    - PTE 하나 = **4MB 청크** (1024 페이지 × 4KB) 를 담당  
- 청크 안에 할당된 페이지가 **하나라도 있으면**  
    - 그 PTE 가 레벨 2 테이블을 가리킨다 (그림의 청크 0, 1, 8)  
- 청크 전체가 미할당이면  
    - 레벨 1 PTE = null → **레벨 2 테이블이 아예 없다** (그림의 청크 2 ~ 7, 9 ~ 1023)  
- 레벨 2 테이블 하나 = PTE 1024 개 × 4B = 4KB = 페이지 하나 크기

### 메모리 절약 두 가지

1. 레벨 1 PTE 가 null 이면 레벨 2 테이블을 만들지 않는다  
    - 대부분의 주소공간이 미할당  
2. 레벨 1 만 항상 메모리에 둔다  
    - 레벨 2 는 필요할 때 만들고 page in / out  
    - 자주 쓰는 레벨 2 만 메모리에 캐시된다

### 주소와 번역

- 주소 : VA = ( VPN1 | VPN2 | VPO ) = ( 10비트 | 10비트 | 12비트 )  
- 번역  
    1. 레벨 1 [VPN1] → 레벨 2 테이블의 주소  
    2. 레벨 2 [VPN2] → PPN  
    3. PA = ( PPN | VPO )  
- k 단계 테이블이면 **PTE 를 k 번 읽는다**  
    - 번역 비용이 늘어난다  
    - → **TLB** 가 이 비용을 줄여 준다

### 64비트 (x86-64)

- 4 단계 × 9 비트  
    - PTE 8B, 표 한 조각 = 4KB = 512 개  
- 36 비트 VPN + 12 비트 VPO = 48 비트
