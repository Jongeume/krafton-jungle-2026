# 9.1 물리 및 가상 주소 방식

> 진척도 이슈 : [#199](https://github.com/Jongeume/krafton-jungle-2026/issues/199)

> [!NOTE]
> **요약**  
> 물리 주소 방식 : CPU 가 **물리주소(PA)** 로 메인 메모리에 바로 접근한다.  
> 가상 주소 방식 : CPU 가 **가상주소(VA)** 를 만들고, MMU 가 PA 로 번역한다.

> [!TIP]
> **비유**  
> VA = 프로그램이 쓰는 "내 사물함 번호".  
> PA = 건물에 실제로 붙은 사물함 번호.  
> MMU = 명부(페이지 테이블)를 보고 내 번호를 실제 번호로 바꿔 주는 관리실.

## 초기 PC — 물리 주소 방식

- 물리주소(PA)  
    - ~~메인메모리의 각 바이트에 저장된 값~~  
    - **정정** : 메인 메모리의 각 바이트 칸이 가진 고유한 **번지수**  
        - 칸에 저장된 값이 아니다  
- 물리 주소 방식 = CPU 가 메모리에 접근할 때 가장 자연스럽다  
- 로드 인스트럭션  
    - ~~디스크에 있는 명령어 읽는 장치?~~  
    - **정정** : 메모리에서 값을 읽어 레지스터에 넣는 **명령어**  
        - 장치가 아니다  
        - 디스크와도 상관없다

### 접근 흐름

1. CPU 가 로드 인스트럭션을 실행한다  
2. 유효 물리주소를 만든다  
3. 메모리 버스로 메인 메모리에 전달한다  
    - 정정 : 주소가 메모리 버스를 타고 메인 메모리로 간다 (메모리 버스 → 메인 메모리 순서)  
4. 메인 메모리가 그 주소의 워드를 읽어 CPU 로 반환한다  
5. 레지스터에 저장한다

## 현대 PC — 가상 주소 방식

- 가상주소(VA) : CPU 가 가상 주소 지정으로 만든다  
    - 아직 정확한 뜻 X  
- MMU (메모리 관리 유닛) : 참조 테이블로 VA 를 번역한다  
- 참조 테이블  
    - 위치 : 메인 메모리  
    - 내용 관리 : 운영체제

### 접근 흐름

1. CPU 가 VA 를 만든다  
2. MMU 가 PA 로 변환한다  
3. 메인 메모리에 접근한다  
4. 그 이후 (추측)  
    - ~~물리페이지 접근 → 캐싱된 디스크의 가상페이지 접근 → 가상주소 접근 → 메모리 버스 → 다시 CPU?~~  
    - **정정** : 메인 메모리가 그 PA 의 워드를 읽어 CPU 로 돌려주면 끝  
        - 디스크나 가상페이지를 다시 거치지 않는다  
        - 디스크는 페이지 폴트가 났을 때만 간다
