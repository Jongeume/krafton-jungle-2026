# 9.1 물리 및 가상 주소 방식

> 진척도 이슈 : [#199](https://github.com/Jongeume/krafton-jungle-2026/issues/199)

## 초기 PC(물리 주소 방식)

~~물리주소(PA) - 메인메모리의 각 바이트에 저장된 값~~  
→ **정정** : 물리주소(PA) = 메인 메모리의 각 바이트 칸이 가진 고유한 **번지수**. 칸에 저장된 값이 아니다.  
물리주소방식 = CPU가 메모리에 접근할 때 가장 자연스러움  
~~로드 인스트럭션 = 디스크에 있는 명령어 읽는 장치?~~  
→ **정정** : 로드 인스트럭션 = 메모리에서 값을 읽어 레지스터에 넣는 **명령어**. 장치가 아니고, 디스크와도 상관없다.

CPU -> 로드 인스트럭션 실행 -> 유효 물리주소 생성 -> 메모리버스로 메인메모리에 전달 -> 메인메모리가 그 주소의 워드를 읽어 CPU로 반환 -> 레지스터 저장  
(정정 : 주소가 메모리버스를 타고 메인메모리로 간다. 순서는 메모리버스 → 메인메모리)

## 현대 PC(가상 주소 방식)

가상주소(VA) - CPU가 가상주소지정으로 생성. 아직 정확한 뜻 X  
MMU(메모리관리유닛) - 참조 테이블로 가상주소 번역  
참조테이블 - 메인메모리에 저장됨, 테이블 내용은 운영체제가 관리

CPU -> VA 생성 -> MMU -> PA 변환 -> 메인메모리 접근 ->  
여기서 이후 과정 추측)  
~~물리페이지 접근 -> 캐싱된 디스크의 가상페이지 접근 -> 가상주소 접근 -> 메모리 버스 -> 다시 CPU?~~  
→ **정정** : 메인메모리가 그 PA의 워드를 읽어 CPU로 돌려주면 끝이다. 디스크나 가상페이지를 다시 거치지 않는다. (디스크는 페이지 폴트가 났을 때만 간다)
