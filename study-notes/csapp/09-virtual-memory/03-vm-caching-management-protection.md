## 9.3 캐싱 도구로서의 VM

> [!TIP]
> **비유**  
> 디스크 = 도서관 서고, DRAM = 내 책상.  
> 지금 보는 책(페이지)만 책상에 올려 둔다.  
> 책상에 없는 책을 펴려 하면 서고에 다녀온다 = 페이지 폴트.  
> 책상이 꽉 차면 한 권을 서고로 돌려놓는다 = 희생 페이지 (메모했으면 원본에 옮겨 적고).

- 가상메모리 = **디스크에 저장된** N 개의 바이트 크기 셀 배열  
    - 가상메모리라 무형일 줄 알았는데, 실존했다  
    - 각 바이트는 특정한 가상주소를 가진다  
    - 가상주소 = 배열의 **인덱스**  
- VM 시스템 : 가상메모리를 블록 단위로 분할해 관리  
    - 배열을 블록 단위로 = 가상주소들을 블록 단위로  
- 가상페이지 = 분할된 블록 (= 분할된 가상주소들)  
    - 크기 : P = 2^p 바이트  
- 물리페이지  
    - 크기 : P 바이트  
    - 다른 이름 : **페이지 프레임**(page frame)

| 가상페이지 상태 | 뜻 |
| --- | --- |
| unallocated | 비할당. 관련 데이터 X, 디스크상 공간 X |
| cached | 할당됨 + 물리 메모리에 캐시됨 |
| uncached | 할당됨 + 물리 메모리에 캐시 안 됨 |

### 9.3.1 DRAM 캐시

- VM 시스템 캐시 = 메인 메모리로 가상페이지를 캐싱  
- 읽기 속도 : SRAM > DRAM(메인 메모리) >>> 디스크(가상페이지)  
- 캐시 미스 비용  
    - ~~잘못된 캐시 접근 → 다시 접근 (이때 첫번째 바이트 접근 비용 발생?)~~  
    - **정정** : 미스가 났을 때 그 페이지를 **디스크에서 가져오는** 비용  
        - DRAM 캐시 미스는 디스크에서 채우니 비싸다  
        - 디스크는 첫 바이트를 읽는 것이 연속 바이트보다 약 10만 배 느리다  
- 연속 바이트 접근 비용 < 첫번째 바이트 접근 비용  
    - → 가상페이지 **크기**가 커진다 (보통 4KB ~ 2MB)  
    - 왜 : 어차피 첫 접근이 비싸니 큰 블록으로 한 번에 많이 읽자  
- 완전 결합성 : 모든 VP 는 어느 PP 에나 둘 수 있다  
- 쓰기 : 디스크 접근 시간이 커서 write-through 대신 항상 **write-back**

### 9.3.2 페이지 테이블

- VM 시스템이 정해야 하는 것  
    - 가상페이지(디스크에 저장된 분할된 가상주소들)가 DRAM 어딘가에 캐시됐는가  
    - 어떤 물리페이지(= DRAM 블록)에 캐싱했는가  
- 미스가 났을 때  
    1. 디스크에서 가상페이지가 어디 있는지 정한다  
    2. 물리 메모리에서 희생자 페이지(물리페이지 = DRAM 블록)를 고른다  
    3. 가상페이지를 디스크에서 DRAM 으로 복사해 희생자 페이지를 교체한다  
- PT (페이지 테이블)  
    - 가상페이지 → 물리페이지 매핑  
    - 물리 메모리에 저장된 **자료구조**  
        - 정정 : '조합'은 OS 소프트웨어 + MMU 의 주소 번역 하드웨어 + 페이지 테이블, 이 셋이 합쳐져 기능을 제공한다는 뜻  
    - PTE (페이지 테이블 엔트리) 의 배열  
- 주소 번역 하드웨어 (MMU 안)  
    - 가상주소를 물리주소로 바꿀 때마다 페이지 테이블을 읽는다  
- PTE  
    - 유효비트(valid) : VP 가 지금 DRAM 에 캐시되어 있는가  
    - 주소 필드  
        1. 유효비트 O : DRAM 안 PP 의 시작 (= cached)  
        2. 유효비트 X  
            - PP == NULL : VP 가 아직 할당 안 됨 (= unallocated)  
            - PP != NULL : 디스크상 VP 의 시작 (= uncached)  
- 완전 결합성 = 어떤 가상페이지든 **어느 물리페이지 칸에나** 넣을 수 있다  
    - ~~물리페이지가 모든 가상페이지를 포함~~ · ~~어디든 접근 가능~~ 이 아니다  
    - **배치**가 자유롭다는 뜻

> 연습문제 9.2 : PTE 개수 = 2^(n−p) (검증 : 네 답 모두 맞음)  
> 1. 12 − 10 = 2 → 2^2  
> 2. 16 − 14 = 2 → 2^2  
> 3. 24 − 21 = 3 → 2^3  
> 4. 36 − 30 = 6 → 2^6

### 9.3.3 페이지 적중

- 상황 : CPU 가 DRAM 에 캐싱된 VP 의 워드 하나를 읽는다  
1. 주소 번역 하드웨어(MMU 안)가 VP 로 PTE 에 접근 → 메모리에서 읽는다  
2. 유효비트 O → VP 가 메모리에 캐시되어 있음을 안다  
3. PTE 안의 물리메모리 주소(PP 의 시작)로 그 워드의 PA 를 만든다

### 9.3.4 페이지 오류

- 페이지 오류 = DRAM 캐시 미스  
    - 주소 번역 하드웨어가 PTE 를 읽었는데 유효비트 X (VP 캐시 X) → 페이지 오류 예외  
- 처리 예시 (VP 3 요청, 희생자 VP 4)  
    1. 커널의 페이지 오류 예외 핸들러 호출  
    2. 희생자 페이지 선택 (PP 3 에 있던 VP 4)  
    3. VP 4 가 변경됐다면 커널이 디스크에 다시 복사  
    4. VP 4 의 PTE 수정 (메인 메모리에 캐시 안 됨)  
    5. VP 3 을 디스크에서 PP 3 으로 복사  
    6. PTE 3 갱신 후 리턴  
    7. 오류 인스트럭션 재시작  
        - 오류 VA 를 주소 번역 하드웨어로 다시 보낸다  
        - VP 3 캐시됨 → 정상 페이지 적중  
- 페이징 (= 스와핑) : 디스크와 메모리 사이 페이지 전송  
    - 디스크 → DRAM : 페이징되어 들어옴  
    - DRAM → 디스크 : 페이징되어 나감  
- 용어 차이 : SRAM 캐시의 **블록** = VM 의 **페이지**  
- 요구 페이징 : 미스가 나는 **마지막 순간까지** 들여오지 않고 기다린다  
    - 현대의 모든 시스템이 쓴다

### 9.3.5 페이지의 할당

1. malloc 호출  
2. 디스크상에 VP 공간을 만든다  
3. PTE 가 새 VP 를 가리킨다

### 9.3.6 지역성

- 작업 집합(working set) = 거주 집합(resident set)  
    - 프로그램이 실제로 활발히 쓰는 **작은** 페이지 집합  
    - 한 번 메모리에 들어오면 그 뒤의 참조는 히트  
- 쓰레싱  
    - 조건 : 작업 집합 > 물리 메모리  
    - 페이지가 계속 들어오고 나가기를 반복

## 9.4 메모리 관리를 위한 VM

> [!TIP]
> **비유**  
> 반마다 사물함 명부가 따로 있다.  
> 같은 "3번"이라도 1반 명부와 2반 명부가 가리키는 실제 사물함이 다르다.  
> 두 명부가 같은 사물함을 적어 두면 = 공유.

- 운영체제가 프로세스마다 별도의 페이지 테이블을 준다  
    - → 프로세스마다 별도의 **가상 주소 공간**  
- 예  
    - 프로세스 i : VP 1 → PP 2, VP 2 → PP 7  
    - 프로세스 j : VP 1 → PP 7, VP 2 → PP 10  
    - → 여러 VP 가 공유된 같은 PP 에 매핑될 수 있다

| 단순해지는 것 | 내용 |
| --- | --- |
| 링킹 | 코드 · 데이터가 물리 위치와 상관없이 같은 포맷 → 위치 독립적인 실행 파일 |
| 로딩 | 로더는 **복사하지 않는다**. VP 할당 + PTE valid 0 + 실행 파일 위치를 가리킴 → 첫 참조 때 페이지 오류로 복사 (요구 페이징) |
| 공유 | 서로 다른 프로세스의 VP 를 같은 PP 로 매핑 (위 예시) |
| 할당 | 연속된 가상 페이지 k 개 ↔ 흩어진 물리 페이지 k 개. OS 가 연속 PP 를 찾지 않아도 된다 |

- 로딩은 "안 읽혔던 부분 — 정리"  
- 할당 → 그림 9.18 → 9.7 의 1 · 2 · 3단 페이지, 4단 페이지 Field

## 9.5 메모리 보호를 위한 도구로서의 VM

> [!TIP]
> **비유**  
> 명부의 칸마다 "열람만 · 쓰기 가능 · 관리자 전용" 도장이 찍혀 있다.  
> 도장과 다르게 쓰려 하면 관리실이 막고(보호 오류) 내보낸다(SIGSEGV).

- 막아야 하는 것  
    - 사용자 프로세스가 자기 읽기 **전용** 코드 섹션을 수정  
    - 커널의 코드 · 데이터 구조를 읽거나 수정  
    - 허용되지 않은 다른 프로세스의 사적 메모리를 읽거나 쓰기  
- 접근 제어 방식  
    1. CPU 가 주소를 만들 때마다 PTE 를 읽는다 → PTE 에 **허가 비트** 추가  
    2. 주소 번역 하드웨어가 가상페이지 접근을 제어  
- 위반 시  
    1. CPU 가 일반 보호 오류를 낸다  
    2. 커널의 예외 핸들러로 제어가 넘어간다  
    3. 핸들러가 SIGSEGV 를 그 프로세스로 보낸다  
        - 정정 : 2 와 3 의 순서가 바뀌어 있었다  
    4. 리눅스 쉘이 "세그먼트 오류" 로 보고한다

## 궁금한 점

### 가상메모리는 왜 디스크의 바이트 배열이고, 바이트마다 가상주소를 가지나

- 처음 가설 : 메인 메모리에서 N 바이트 워드를 CPU 에 넘길 때, 그 워드가 디스크의 가상페이지였고 메인 메모리에 캐싱돼 있어서?  
- **결론** : 가상주소 = 배열의 인덱스, 그 칸의 바이트 = 실제 값(데이터)  
    - 원본 배열은 디스크, CPU 가 읽는 건 DRAM 에 캐싱된 복사본  
    - 디스크에 VA 를 "저장"하는 게 아니다  
    - `char a[100]` 의 a[5] 에서 5 가 메모리에 저장되지 않는 것과 같다 — 위치가 곧 인덱스  
- **왜 "배열 + 바이트마다 주소"인가**  
    - CPU 의 load / store 가 바이트 단위 주소를 받는다  
    - 물리 메모리도 "M 바이트 배열, 물리주소 = 인덱스" 로 보인다  
    - 프로그램에게 같은 모양(평평한 바이트 배열)을 더 크게 보여 주는 게 가장 단순한 약속  
- **왜 "디스크에"인가**  
    - 주소공간(x86-64 실제 2^48 = 256TB)이 DRAM 보다 훨씬 크다  
    - 전체 원본을 담을 수 있는 건 아래층의 큰 저장장치(디스크)뿐  
    - DRAM 은 원본 일부의 **캐시** (L1 이 DRAM 을 캐싱하는 관계가 한 칸 아래로)  
- **접근 흐름**  
    1. CPU 가 VA 계산  
    2. MMU 가 페이지 테이블에서 PTE 확인  
    3. valid 1 → PA 로 바꿔 DRAM 에서 읽기 (hit)  
    4. valid 0 → page fault → OS 가 디스크에서 DRAM 으로 복사 → 명령 재실행  
- **CPU 는 VA 를 어디서 얻나** : 명령어가 계산한 평범한 숫자  
    - 명령어 fetch : PC(`rip`) 값  
    - load · store : 유효주소 = 레지스터 값 + 변위 (`mov rax, [rbx+8]` → rbx + 8)  
    - 숫자의 최초 출처  
        - 링커 : 코드에 박힌 주소 · 변위  
        - 커널 execve : rip = 진입점, rsp = 스택 VA 초기값  
        - mmap / malloc : 커널이 골라 준 VA 가 포인터 변수에 저장  
    - CPU 는 그 숫자가 "가상"인지 모른다. MMU 가 VA 로 해석해 바꿀 뿐  
    - → "디스크 배열 + 인덱스 = VA" 는 **OS 와 MMU 가 숫자 위에 씌운 정의**  
- **VA 숫자가 실제로 있는 곳** : 레지스터 · 포인터 변수 (일반 데이터 값으로)  
    - 디스크에는 페이지 **내용**만 있고 VA 는 없다  
    - 정정 : 페이지 테이블에도 VA 는 없다  
        - VPN 은 표의 **인덱스**  
        - 표에 적히는 건 PPN 또는 디스크 위치

### 가상 주소 공간 vs 가상 메모리

- 가상 주소 공간 : 가상주소들의 집합 (번지수 목록 자체)  
- 가상 메모리 : 바이트 배열, 가상주소를 인덱스로 쓴다  
    - 번지수 = 가상주소  
    - 그 칸의 내용 = 바이트 값
